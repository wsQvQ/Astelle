## 0. 「接口留了吗」——诚实盘点

| 件 | 现状 |
|---|---|
| 设置入口（侧栏底坞「设置」） | ✅ 有（`DockBtn(Tune, "设置")`） |
| 导航路由 | ✅ 有（`AstelleDestination.Settings`） |
| 页面壳 | ✅ 有（`SettingsScreen`，目前是占位符） |
| 主题色板接口 `LocalAstelleColors` | ✅ 有 —— 换配色方案 = 换一个 Provider，架构不挡路 |
| **偏好持久层** | ❌ 没有（SharedPreferences / DataStore 均未引入） |
| **真实可调的设置项** | ❌ 一个都没接（全靠代码常量） |

结论：**骨架留了五成，"能用的设置"是零**。本计划就是把后两行补上。

## 1. 视觉框架（照用户图）

- 页头：大标题「设置」+ 左上侧栏钮（已有）
- 分组：Accent 小标（通用设置 / 编辑与数据 / 关于）+ **大圆角暖白卡片组**
- 行：左图标（线性、`Muted`）+ 标题（Ink）+ 副标（Muted 小字）+ 尾部控件（下拉/开关/无）
- 语言：暖纸色系、弱描边、无重阴影 —— 和现有抽屉/菜单同一套

## 2. 设置项（按「先便宜后贵」排）

### 组 1 · 通用设置
1. **卡片默认密度**（接 C 的收起/展开开关）—— 展开 / 收起。最便宜，先做
2. **颜色模式**：浅色 / 跟随系统 —— ⚠️ 深色是**新色板**（一晚），v1 只留浅色+跟随系统（跟随=浅色占位）
3. **动态取色**（Monet，Android 12+，默认关）—— 讨论 B 的归宿；`dynamicLightColorScheme`
   映射进 `LocalAstelleColors` 即可，架构已留口

### 组 2 · 编辑与数据
4. **图片压缩档位**：标准（1600px/85%）/ 高质量 / 省空间 —— 改 `ImageStore` 的两个常量成参数
5. 自动保存、`updatedAt` 语义：**不做开关**（产品口径写死，不留旋钮）

### 组 3 · 关于
6. 版本号（随发布四件套走 1.21.0）、开源许可（Markwon/Compose/Coil）、
   「本地优先，数据都在你手机里」的数据说明

## 3. 技术方案

- **持久层：`SharedPreferences`**（零新依赖；⚠️ 构建离线，DataStore 要先查缓存）
  + Hilt 提供 `SettingsRepository`（读写各一个方法级别的小接口）
- 状态：`SettingsViewModel` 暴露 `StateFlow<UserSettings>`；密度/取色/压缩档位各一个字段
- 消费点：DrawerSheet（密度默认值）、AstelleTheme（取色/模式）、ImageStore.import（压缩档位）

## 4. 实施顺序（一晚内可交 v1）

1. 框架（分组+卡片行组件）+ 关于组（纯静态，先把脸撑起来）
2. SharedPreferences + SettingsRepository + 卡片默认密度接通（第一个真设置）
3. 压缩档位（改常量为参数）
4. Monet 取色（设置里开关，默认关）
5. 颜色模式「深色」→ 单独立项（新色板一晚，不塞进 v1）
