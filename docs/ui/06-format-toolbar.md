# 06 · 编辑器格式工具栏（计划稿，未实现）

> 用户原话：「你猜一下我们软件还差什么东西（图 2）」—— 图 2 是另一款编辑器的
> 格式工具栏：B / I / U / 对齐 / 高亮 / `<>` / H1 H2 H3 / 列表 / 有序列表 / 任务 / 引用，
> 浮在键盘上方。
>
> 用户要求：**先计划、做功能取舍和优化，再写代码**。

## 1. 目标与不做

**目标**：写 Markdown 不用再手敲 `#` `**` `-`，一键完成 90% 的格式操作。

**不做**：
- 不做「所见即所得」富文本编辑器（我们是 Markdown 源码编辑 + 预览，这是产品定位）
- 不做选区格式状态高亮（v1 不做，见 §5）
- 不做对齐（Markdown 没有对齐语法，靠 HTML 会污染 .md）

## 2. 出现位置

**只在键盘弹出时出现**，贴在键盘上沿（`WindowInsets.ime`），键盘收起即隐藏 ——
它是「键盘的附件」，不是常驻工具条。理由：不占常驻空间、离光标最近、和手机上的
写作 App 一致。平板横屏全展开不滚动；手机横向可滚动一行。

视觉沿用现有语言：`Paper` 底 + 顶部一道 `Divider` 发丝线；图标 20dp、`Muted` 静音色；
按压态 `AccentMist`（和顶栏按钮一致）；触控 44dp。

## 4. 交互规则（核心）

1. **有选区** → 包住它（`**选中**`），选区保持选中包住后的内容
2. **无选区** → 插入成对符号，光标落在**中间**（`****` → 光标在第二、三个星号之间）
3. **行级操作**（标题/列表/任务/引用）→ 定位光标所在行：
   - 已是该前缀 → 移除（**切换**）
   - 是别的前缀（如 `- ` 换成 `# `）→ **替换**
   - 都没有 → 加上
4. **每次操作 = 一次撤销**（走 `onContent` 一条路，撤销/自动保存语义不变）
5. 操作后**光标跟着走**（插模板时光标落模板内，包住时保持选区）

## 5. 技术要点

- **`BasicTextField` 要从 `String` 换成 `TextFieldValue`**：现在 `value: String`
  拿不到光标位置，没法做「包住选中」「光标居中」。这是本轮唯一的结构性改动
  （`HomeUiState.content` 仍是 String，只有编辑框这一层持有 `TextFieldValue`）
- 工具栏本身**静态**、不随按键重组（放 `remember`，只在选区变化时算高亮）
- 键盘高度用 `WindowInsets.ime`，工具栏放 `imePadding` 容器里，别和正文的
  `imePadding` 叠加（正文那处要去掉）
- 图标用 material-icons-extended：`FormatBold` / `FormatItalic` / `FormatStrikethrough` /
  `FormatListBulleted` / `FormatListNumbered` / `FormatQuote` / `Code` / `Link` /
  `HorizontalRule` / `Title`…；H1~H3 用**文字**（比图标清楚，图 2 也是文字）

## 6. 优化点

- 手机上一行横向滚动，`LazyRow` + 边缘渐隐提示「右边还有」
- 表格模板插入后光标落在第一个单元格内，直接打字
- 连续点击同一切换项（如 H1）不会堆出 `# # `（切换逻辑保证）
- 中文输入法组字期间不插符号（`onValueChange` 的 composing 区间要避开）—— ⚠️ 实现时验证

## 7. 需要拍板的三件事

1. **下划线 / 高亮要不要？** 非标准 Markdown，得靠 HTML `<u>` / `<mark>`，
   导出的 .md 里是 HTML 标签（多数渲染器认，但纯 Markdown 预览器不认）
2. **表格模板要不要**（一键插 2×2 骨架）？我建议要
3. **格式状态高亮**（光标在粗体里 → 加粗按钮点亮）放 v1 还是 v2？我建议 **v2**
   （要解析光标周边的 Markdown 上下文，值得做但不该挡第一版）
